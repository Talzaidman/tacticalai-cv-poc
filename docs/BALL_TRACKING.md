merged by distance. WASB's own online tracker is not used. SAM 3 and the 3-frame WASB
windows use future frames (offline). Clip 1 is 640x360, so the ball is a few pixels wide.

## Quality correction: crowd false positives and local-only filtering

**The basketball-specific detector is not reliable on these clips.** Visual
review confirmed that crowd false detections inflated the earlier 106/150 and
132/175 "observed" counts. These are not true-ball detection rates. In particular,
failure to associate most observations with people must not be interpreted as
evidence of airborne balls: many observations were simply false.

Added a draft, evaluation-only reference in
[`configs/evaluation/ball_reference.json`](../configs/evaluation/ball_reference.json).
It contains 32 sampled frames; 11 development and 8 reserved evaluation samples
have visible approximate centers. The other 13 are ambiguous/occluded and
excluded, **not negative examples**. Coordinates use a 1280 x 720 review canvas,
with a 14 px localization tolerance and at most one true positive per frame.
Additional predictions, including unmerged duplicates, count as false positives.
These assistant-reviewed labels are not independently human-certified ground
truth. Fixed frame splits are temporally correlated samples of the same two
videos, not independent-video validation.

Local-only probes tested the existing generic YOLO26s, basketball YOLO26m and
shot-domain YOLOv8n checkpoints, smaller tiles, person-context crops and motion
blobs. None established reliable recall. The small-tile YOLO26m development probe
found 5/11 reference balls but produced 93 false candidates; a generic
person-crop probe found 4/11 with 28 false candidates. Camera-compensated color
blobs found 2/11 with 211 false candidates and are not used as ball observations.
No additional model/archive downloads were made after the local-only restriction;
the abandoned incomplete ONNX download was removed.

### Separate camera-motion background-rejection run

`outputs/ball-motion-filter-v1` reuses **the exact original YOLO26m raw
detections** and person/camera observations, without rerunning any detector.
An affine camera transform is robustly fitted from scene features between the
current frame and available neighbors two frames away. At 640 px working width,
the median per-box photometric residual must be at least 25/255. When both
neighbors are available the lower residual is used. Unsupported registration,
image-warp borders and camera-cut crossings cannot supply motion evidence.
Threshold selection used development samples only; the reserved split was
scored after freezing the pipeline.

This is **background rejection, not a new ball detector**. It can remove true
balls held relatively still, and moving spectators/objects can still pass.
No floor mask is applied to ball candidates, so airborne image detections remain
eligible. This filter does not use the experimental blob color/shape scores.
Processing is offline, using future frames when available; it is not causal
real-time inference. No reference coordinates or manual role labels enter it.

Counts below are after size filtering and duplicate NMS (`accepted`), not raw
tile hits or tracking status:

| Split | Run | True positives | False positives | Missed visible balls |
|---|---|---:|---:|---:|
| Development, 11 visible frames | Original YOLO26m | 2 | 74 | 9 |
| Development, 11 visible frames | Motion-filtered YOLO26m | 2 | 6 | 9 |
| Reserved evaluation, 8 visible frames | Original YOLO26m | 1 | 42 | 7 |
| Reserved evaluation, 8 visible frames | Motion-filtered YOLO26m | 1 | 4 | 7 |

On the reserved samples false candidates fell from 42 to 4, but recall remained
**1/8 (12.5%)**, with precision **1/5 (20%)**. Clip 1 still has **0/4** localized
balls on each split. The filtered tracker has 2/150 and 76/175 `observed` frames,
which again are status counts, not accuracy. Reserved tracked observations are
0 TP / 0 FP / 4 FN in clip 1 and 1 TP / 2 FP / 3 FN in clip 2.
Control remains unknown throughout clip 1; the two clip 2 controller hypotheses
are not validated possession labels.

Both full filtered videos decoded to 150/175 frames. Raw detections, people,

## Pipeline

### High-visibility detection overlay

Every raw detector box is now displayed with a large orange ring, center dot
and confidence label, including tentative, ambiguous and tracker-rejected
detections. Duplicate full-frame/tile detections can overlap. Orange means
detector evidence, not a verified true ball or confirmed track. Predictions
use a gray X, not an orange detection marker. Tracking, controller decisions
and minimap semantics are unchanged.

Re-render saved results without running any model:

```powershell
python -m tacticalai.ball_cli --render-only --videos . `
  --source outputs\ball-basketball-v1 `
  --output outputs\ball-basketball-v1\orange-review
```

The ball pipeline is independent of player tracking. It can consume completed
automatic person/camera caches without changing any existing person observation.
If those caches are unavailable, it can create a **new** BoT-SORT person baseline
with ReID off and `sparseOptFlow` GMC. Fresh tracks are run-local person
hypotheses, not the previous TrackTrack/ReID identities. Roles, teams and jersey
numbers remain unknown in fresh runs.

## Method and output semantics

- Detect only the configured ball class. Full-frame inference optionally adds
  overlapping crops; all boxes return to original source-image coordinates.
  IoU NMS merges duplicates and preserves the selected detection's provenance.
- Reject oversized ball candidates. Associate candidates using confidence and
  a constant-velocity image-space gate. Two consecutive supported detections
  confirm a track; ambiguous candidates are not forced into a measurement.
- Output `tentative`, `observed`, `predicted` or `unknown`. Predictions last at
  most 0.12 seconds, stay separate from measured coordinates, and cannot
  establish control. Gaps require renewed observation confirmation.
- Estimate a controller only after at least three consecutive frames at 25 FPS
  with sufficiently strong and unambiguous ball/body proximity. Reset on
  missing evidence, ambiguity, identity segment changes, ball reacquisition,
  controller changes or detected cuts. Scores are **uncalibrated heuristics**,
  not probabilities.
- Boxes allow lateral hands and low dribbling, but this is **not hand/pose
  detection, verified dribbling, or tactical possession recognition**.
  An overlapping defender or a passing ball can still cause a wrong estimate.
  Release/pass/shot classification is not implemented; unassigned control is
  unknown, not automatically labelled a pass or shot.
- Person candidates use existing automatic identities, not manual roles.
  Unknown-role persons may receive a controller hypothesis; this does not
  classify them as players. Unlinked detections without an identity cannot.
- The orange **minimap ring** is at the estimated controller's floor position.
  It is not the ball's measured position and is only available with a valid
  inside-court person projection. An airborne ball center is never passed
  through the floor homography. `ball.court_xy_m` always remains `null`.
  A missing controller or projection removes the ring immediately.
- Cut detection combines a conservative thumbnail difference heuristic and
  source camera shot boundaries, when present. Subtle cuts can still be missed.

The native-controls page contains only the two videos and a limitations notice.
No manual corrections or labels enter inference. Existing source silhouettes,
identities, automatic classifications and coordinates are preserved.

## Reproduction

From the repository root, install the existing runtime and preview dependencies
in the chosen environment. Geometry uses the existing SciPy dependency:

```powershell
python -m pip install -e ".[preview,geometry]"
$env:PYTHONPATH = "$PWD\src"
```

Use the original `data\raw` directory, or `--videos .` for the two root-level
clips in this checkout. Never replace or modify the source videos.

### Generic baseline with new people and automatic court estimates

```powershell
python -m tacticalai.ball_cli --videos . --output outputs\ball-baseline-new `
  --model models\yolo26s.pt --person-model models\yolo26s.pt `
  --device cpu --imgsz 1280 --tiles --automatic-court
```

The optional `--automatic-court` path uses the existing KaliCalib challenge
checkpoint/refinement and short floor-feature propagation, not manual
calibration. It downloads pinned KaliCalib assets if absent. Failures stay
unavailable, with no mean-camera or manual fallback. Court dimensions are an
explicit 28 x 15 m assumption; projections are unverified and not the earlier
offline-smoothed benchmark. Model/license provenance is saved.

If a corporate certificate/proxy blocks Python's model download, pre-download
the official checkpoint through the organization's trusted HTTPS configuration
and supply the local path. Do not disable TLS verification:

```powershell
New-Item -ItemType Directory -Force models
Invoke-WebRequest -UseBasicParsing `
  https://github.com/ultralytics/assets/releases/download/v8.4.0/yolo26s.pt `
  -OutFile models\yolo26s.pt
```

### Basketball-specific comparison on identical people/cameras

[Checkpoint provenance](../configs/ball_model_game.json) pins the upstream
repository revision, URL, SHA-256, class and license caveats. Download the
checkpoint to `models\basketball-game.pt` using trusted HTTPS:

```powershell
$model = Get-Content configs\ball_model_game.json -Raw | ConvertFrom-Json
Invoke-WebRequest -UseBasicParsing $model.weights_url -OutFile models\basketball-game.pt
python -m tacticalai.ball_cli --videos . --source outputs\ball-baseline-v2 `
  --output outputs\ball-basketball-new --model models\basketball-game.pt `
  --ball-class 0 --model-provenance configs\ball_model_game.json `
  --device cpu --imgsz 1280 --tiles
```

This checkpoint has class 0 `Ball` and other game-specific jersey/referee classes.
**Only class 0 is consumed.** Its other classes never assign roles, teams,
jersey numbers or person IDs here. The uploader declares MIT, but that does not
settle underlying architecture, training-data or commercial rights; review
Ultralytics licensing separately. The card describes one university game, not
verified generalization to these broadcast clips.

To integrate with the earlier automatic presentation when restored, substitute
`--source outputs\team-colors-floor-v1`. Do not pass `--automatic-court` with
`--source`. Sources must be complete, explicitly automatic, frame/hash/video
aligned and free of manual calibration/classification provenance.

The same module can run on Colab with `--device 0` and transferred source
caches/videos. Exported postprocessing and review remain CPU-compatible.

## Artifacts and validation

Each run stores:

- `experiment.json`: configuration, model hashes, class selection, versions,
  source hashes, licenses/provenance and limitations.
- Per clip `frames.jsonl`: unchanged source tracks/camera fields, raw ball
  detections, merged candidates, track status, controller candidates and reasons.
- Per clip `ball.csv`: one record per frame; measured and predicted image
  centers are separate. Ball court coordinates remain empty; marker coordinates
  have their own `estimated_controller_floor_position` provenance.
- Per clip `annotated.mp4`, review snapshots and `metadata.json`: decoded-frame
  checks, status counts, processing times and artifact hashes.
- `run_source` and `environment.txt`: executed source snapshot and dependencies.

All model assets, source videos and outputs are Git-ignored. A fresh output
directory is required; failed runs are labelled failed rather than successful.
Total run timing includes setup; per-clip detector time excludes player/camera
work in the cached comparison. Playback FPS is not inference throughput.

Focused checks:

```powershell
$env:PYTHONPATH = "$PWD\src;$PWD"
python -m pytest tests\test_ball.py tests\test_silhouette_presentation.py `
  tests\test_role_team.py tests\test_minimap.py tests\test_automatic_presentation.py `
  tests\test_floor_context.py tests\test_unlinked_people.py -q
```

Tests cover confirmation/gap thresholds, cuts, ambiguity, ID changes, source
isolation, tile coordinates/class selection, marker semantics and actual MP4
encoding/decoding. These software checks and detection-status coverage **are
not accuracy measurements**. Held-out ball center/visibility annotations and
controller intervals are still required for precision/recall, localization
error, controller accuracy/abstention coverage and transition timing.
